PDF 1 - GPU Architecture and CUDA

#01 - Why GPU? ⚡ The Power Problem

Key Points

  • General purpose processors max out at IPC of 4-6 — not enough for heavy computation
  • Programs like weather simulation, image recognition need massive ILP (Instruction Level Parallelism)
  • Solution: Create processors with 100s of ALUs for parallel computation
  • GPU approach: Simple ISA + limit irregular memory accesses + hundreds of simple cores
  • Trade-off: Dedicate area to ALUs → simplify fetch/decode/schedule logic
SUPER EFFECTIVE! (Exam Focus)

GPUs sacrifice single-thread performance for massive parallel throughput. They have simple cores but LOTS of them.

What limits CPU performance for scientific computing?
Click to reveal

IPC maxes at 4-6, power constraints prevent scaling issue width beyond 6 instructions/cycle

Why can GPUs exploit linear algebra well?
Click to reveal

Matrix ops have N² independent additions with no dependencies — massive ILP that maps perfectly to parallel ALUs

#02 - GPU Evolution 🎮 Early Days

Key Points

  • Graphics originated in 70s — CAD and flight simulation
  • Vector Graphics: Define shapes by coordinates (scalable, small storage)
  • Raster Graphics: Store pixel-by-pixel matrix (good for effects like illumination, shadows)
  • Single-pass pipeline preferred: Images enter → transform → display
  • Shader programs born — small programs for vertex/pixel processing (rotation, shading, illumination)
  • Shader languages made hardware-independent for portability across GPUs
SUPER EFFECTIVE! (Exam Focus)

Vector graphics = coordinates (scales well). Raster graphics = pixel matrix (better for effects). Modern GPUs support both.

Vector vs Raster Graphics?
Click to reveal

Vector: 4 floats define a rectangle, scales perfectly. Raster: stores every pixel's color, better for illumination/shadows/blurring

What is a Shader?
Click to reveal

A small program that processes vertices/pixels to apply transformations like rotation, shading, or illumination

#03 - Graphics Pipeline 🔧 Rendering
Graphics Rendering Pipeline Stages — click to enlarge

Key Points

  • Graphics pipeline synthesizes (renders) images, not just displays them
  • 4 main stages: Vertex Processor → Rasterizer → Fragment Processor → Pixel Engine
  • PTX (Parallel Thread eXecution): NVIDIA's virtual ISA — platform independent
  • SASS (Shader ASSembler): Device-specific native ISA, compiled from PTX
  • Triangles are the fundamental primitive — always planar, easy to compute ray intersections
  • Moving/rotating/scaling triangles = matrix operations → perfect for GPU parallelism
SUPER EFFECTIVE! (Exam Focus)

PTX is virtual (portable) ISA → compiled to SASS (device-specific) at runtime via JIT. This ensures backward compatibility across GPU generations.

Why triangles for 3D graphics?
Click to reveal

3 vertices always coplanar, efficient ray-triangle intersection, easy to apply textures, transforms are just matrix ops

PTX vs SASS?
Click to reveal

PTX = virtual portable ISA (like Java bytecode). SASS = native device-specific machine code. PTX→SASS via JIT compilation

#04 - Polymorph Engine 🔷 Modern Pipeline
Polymorph Engine 5-Stage Pipeline — click to enlarge

Key Points

  • Polymorph Engine replaced the simple Vertex Processor in modern GPUs (NVIDIA Fermi+)
  • 5-stage pipeline: Vertex Fetch → Tessellation → Viewport Transform → Attribute Setup → Stream Output
  • Vertex Fetch: Converts object-space coords → world coords, vertex shading + hull shading
  • Tessellation: Breaks polygons into smaller triangles for surface detail
  • Hull Shader: Controls granularity — finer for near objects, coarser for far objects
  • Viewport Transform: Clips 3D scene to visible portion, handles aspect ratio scaling
  • Attribute Setup: Computes plane equations for illumination (dot product of normal & light rays)
SUPER EFFECTIVE! (Exam Focus)

Polymorph Engine's 5 stages: Vertex Fetch → Tessellation → Viewport Transform → Attribute Setup → Stream Output. Delegates work to Streaming Multiprocessors (SMs).

What does the Hull Shader do?
Click to reveal

Divides polygons into smaller polygons — finer granularity for near objects, coarser for far objects

What is Tessellation?
Click to reveal

Breaking down polygons into smaller triangles and line segments to create more surface detail

#05 - Rasterization & Fragments 🎨

Key Points

  • Rasterization: Converts triangles → pixel fragments by overlaying a grid
  • Fragment Processor computes final color of each pixel fragment
  • Goraud Shading: Simple linear interpolation (assumes flat triangle surface)
  • Phong Shading: Smoothly varying normal vector, more complex reflectivity model
  • Texture Mapping: Maps pre-defined textures to triangle surfaces for realism
  • Distance Fog: Pixels farther away colored differently to give depth perception
  • Pixel Engine: Populates frame buffer (2D color matrix → sent to monitor)
  • Z-depth buffering: Determines which fragments are visible/hidden in 3D
  • Alpha channel: 0.0 (transparent) to 1.0 (opaque) for transparency effects
SUPER EFFECTIVE! (Exam Focus)

Goraud = fast, flat interpolation. Phong = smooth normals, better quality. Both compute pixel colors from vertex colors + light + reflectivity.

Goraud vs Phong Shading?
Click to reveal

Goraud: linear interpolation, flat surface assumption, fast. Phong: smooth varying normals, complex reflectivity, better quality

What is the frame buffer?
Click to reveal

Simple 2D matrix holding color info for each pixel on screen — directly sent to the monitor for display

#06 - CUDA & GPGPU Programming ⚙️

Key Points

  • CUDA (Compute Unified Device Architecture) released by NVIDIA in Feb 2007
  • GPGPU = General Purpose GPU — not just graphics anymore
  • nvcc compiler: Separates CPU code and GPU code, compiles GPU→PTX→SASS
  • Fat binary: Contains PTX code + pre-compiled machine code for different GPU models
  • JIT compilation: PTX compiled at runtime to optimize for specific GPU hardware
  • Two-step compilation: C++/CUDA → PTX (virtual ISA) → SASS (device-specific)
  • PTX: RISC-like ISA with infinite registers, single assignment form
SUPER EFFECTIVE! (Exam Focus)

Compilation flow: CUDA C++ → nvcc → PTX (virtual) → JIT/ptxas → SASS (native). Fat binary contains multiple ISA images for portability.

What is a Fat Binary in CUDA?
Click to reveal

A single binary containing PTX code AND pre-compiled machine code for different GPU models — ensures portability

Why JIT compilation for GPUs?
Click to reveal

GPUs change significantly every generation. JIT lets old PTX code run optimized on new hardware

#07 - Kernels, Threads, Blocks & Grids 🧱
Thread → Block → Grid Hierarchy — click to enlarge

Key Points

  • Kernel: Function executed on GPU, invoked by CPU host code (__global__ directive)
  • Thread: Separate program instance on GPU, shares address space, has unique threadIdx
  • Block: Group of threads (1D/2D/3D arrangement), max 768-1024 threads per block
  • Grid: Collection of blocks (1D/2D/3D), blocks execute independently
  • threadIdx.x/y/z: Thread's position within block
  • blockIdx: Block's position in grid, blockDim: dimensions of each block
  • dim3: Built-in 3-tuple type for specifying dimensions (defaults unspecified to 1)
  • Threads within a block can synchronize via __syncthreads() (barrier)
  • Blocks scheduled in any order — must be independent, no inter-block sync
SUPER EFFECTIVE! (Exam Focus)

Hierarchy: Thread → Block → Grid. Threads in same block CAN sync (__syncthreads). Blocks in grid CANNOT sync — execute independently in any order.

Thread vs Block vs Grid?
Click to reveal

Thread = single execution unit. Block = group of threads (can sync). Grid = group of blocks (independent, no sync)

What does __syncthreads() do?
Click to reveal

Acts as a barrier — all threads in a block must reach this point before any thread proceeds past it

How to compute global thread index for 2D?
Click to reveal

row = blockIdx.y * blockDim.y + threadIdx.y, col = blockIdx.x * blockDim.x + threadIdx.x

#08 - GPU Memory & CUDA Memory Ops 💾
CUDA Memory Model & Thread Hierarchy — click to enlarge

Key Points

  • Two separate memory spaces: CPU (host) and GPU (device) — explicit data management
  • Memory hierarchy: Per-thread local → Shared memory (block) → Global memory (all threads)
  • Read-only memories: Constant memory + Texture memory
  • cudaMalloc(): Allocate space in global memory on GPU
  • cudaMemcpy(): Copy data between host↔device with direction flag
  • Direction flags: cudaMemcpyHostToDevice, cudaMemcpyDeviceToHost
  • cudaFree(): Free GPU memory
  • cudaMallocPitch() for 2D, cudaMalloc3D() for 3D arrays — handle alignment
  • Shared memory: 64-128KB per SM, accessed via __shared__ specifier
SUPER EFFECTIVE! (Exam Focus)

CUDA memory flow: cudaMalloc (GPU) → cudaMemcpy (CPU→GPU) → kernel execution → cudaMemcpy (GPU→CPU) → cudaFree

GPU Memory hierarchy (fastest→slowest)?
Click to reveal

Registers → Shared Memory (block-level, 64-128KB) → L1 Cache → L2 Cache → Global Memory (DRAM)

What are the CUDA memory functions?
Click to reveal

cudaMalloc (allocate), cudaMemcpy (transfer), cudaFree (deallocate). For 2D/3D: cudaMallocPitch, cudaMalloc3D

#09 - Streams, Graphs & Events 🌊

Key Points

  • Problem: Sequential phases (ToGPU → Compute → ToCPU) waste time
  • Stream: Sequence of commands executing in order, initiated by host threads
  • Multiple streams execute independently — no ordering across streams
  • With 2 streams: execution time reduced from 3 units to 2 units (33% speedup)
  • More streams = more overlap = more speedup (if device supports concurrent execution)
  • CUDA Graphs: Reduce overhead of launching many short-duration kernels
  • Graph nodes: Kernels, CPU function calls, memory copy/init, child graphs
  • Edges define dependencies — runtime pre-computes schedule, prefetches data
SUPER EFFECTIVE! (Exam Focus)

Streams overlap ToGPU/Compute/ToCPU phases. Graphs reduce kernel launch overhead by pre-computing the execution schedule for an ensemble of tasks.

How do streams improve performance?
Click to reveal

By overlapping data transfer and computation phases — e.g., stream 1 computes while stream 2 transfers data

When are CUDA Graphs useful?
Click to reveal

When launching many short-duration kernels — reduces setup overhead by pre-computing schedule and prefetching

#10 - GPU Architecture 🏗️ GPC/SM/PB
GPU Architecture Hierarchy — GPC / TPC / SM / PB — click to enlarge

Key Points

  • GPU connected to CPU via PCI Express or on same die (e.g., Intel Sandy Bridge)
  • Giga Thread Engine: Hardware scheduler for threads across compute units
  • GPU divided into 6 GPCs (Graphics Processing Clusters)
  • Each GPC: 1 Raster Engine + 7 TPCs (Texture Processing Clusters)
  • Each TPC: 1 Polymorph Engine + 2 SMs (Streaming Multiprocessors) → Total 84 SMs
  • L2 Cache: 4-6 MB shared across GPU
  • HBM2 (High Bandwidth Memory 2) via multiple memory controllers
  • NVLink: High-bandwidth interconnect for multi-GPU systems
  • SM internals: Instruction Cache, L1 Cache, Texture Cache, Constant Cache, Shared Memory (64-128KB)
SUPER EFFECTIVE! (Exam Focus)

GPU hierarchy: GPU → 6 GPCs → 7 TPCs each → 2 SMs each = 84 SMs total. Each SM has 4 Processing Blocks (PBs).

What is a GPC?
Click to reveal

Graphics Processing Cluster — contains 1 Raster Engine + 7 TPCs. GPU has 6 GPCs total

What is inside a TPC?
Click to reveal

1 Polymorph Engine (vertex processing) + 2 Streaming Multiprocessors (SMs) for compute

#11 - SM & Processing Block Details 🔬
SM & Processing Block Internal Structure — click to enlarge

Key Points

  • Each SM has 4 Processing Blocks (PBs) + 4 texture processing units
  • Each PB contains: 16 INT cores + 16 FP32 cores + 8 FP64 cores + 2 Tensor cores
  • Also per PB: 8 LD/ST units + Special Function Unit (SFU) for transcendentals/trig
  • PB pipeline: Instruction Buffer → Scoreboard Scheduler → Dispatch → Register File → Compute
  • Simple in-order pipeline — no rename tables or reservation stations (saves power/area)
  • Streaming Processors (SPs) contain fully pipelined functional units
  • MAD (Multiply-And-Add) instruction: a = a + b*c — key for matrix operations
  • SFU also handles pixel color interpolation for fragment processing
SUPER EFFECTIVE! (Exam Focus)

Per PB: 16 INT + 16 FP32 + 8 FP64 + 2 Tensor cores + 8 LD/ST + 1 SFU. Simple in-order pipeline (scoreboard-based, no OOO) to save power.

What cores does each Processing Block have?
Click to reveal

16 integer, 16 single-precision FP, 8 double-precision FP, 2 tensor cores, 8 LD/ST units, 1 SFU

Why no OOO execution in GPU cores?
Click to reveal

Too many cores — OOO hardware (rename tables, reservation stations) would consume excessive power and area

#12 - Warps & SIMT Execution 🌀
SIMT Warp Execution & Branch Divergence — click to enlarge

Key Points

  • SIMT = Single Instruction, Multiple Thread (NVIDIA's execution model)
  • Warp = group of 32 threads scheduled together on a PB
  • Lockstep execution: All threads execute same instruction simultaneously on different data
  • Scheduler picks next instruction → sends to ALL cores in warp
  • If one thread's memory access is slow (cache miss), ALL threads wait
  • This is acceptable because GPU workloads have regular, co-located memory access patterns
  • Varying execution times can cause performance degradation when accesses straddle cache lines
SUPER EFFECTIVE! (Exam Focus)

SIMT: All 32 threads in a warp execute the SAME instruction in lockstep, but on DIFFERENT data. If any thread stalls, ALL wait.

What is SIMT?
Click to reveal

Single Instruction Multiple Thread — 32 threads in a warp execute same instruction in lockstep on different data pieces

What happens on a cache miss in a warp?
Click to reveal

ALL threads wait until the slowest thread completes — lockstep means no thread runs ahead

#13 - Branch Divergence & Predication 🔀
Predicated Execution with Mask — click to enlarge

Key Points

  • Branch Divergence: Different threads take different paths (if/else) — breaks lockstep
  • Solution: Predicated Execution — ALL threads execute ALL paths
  • Correct path instructions: executed and committed to architectural state
  • Wrong path instructions: processed but results DISCARDED (thread still waits in lockstep)
  • 32-bit mask per warp: bit i = 1 means thread i should execute current instruction
  • Stack-based tracking: Push 1 (correct path) or 0 (wrong path) when entering branch
  • Instruction committed only if ALL stack entries are 1 (on correct path of all branches)
  • Reconvergence point: instruction where all divergent threads rejoin after branch
  • Nested branches handled by growing the stack per thread
SUPER EFFECTIVE! (Exam Focus)

Predicated execution: ALL threads execute ALL branch paths in lockstep. A 32-bit mask tracks which threads are on the correct path. Stack handles nested branches.

How do GPUs handle if-else with SIMT?
Click to reveal

Predicated execution — all threads execute both paths. Mask bits determine which threads commit results. Wrong-path results discarded.

What is a reconvergence point?
Click to reveal

An instruction just outside all conditional statements where all divergent threads rejoin and resume normal lockstep execution

#14 - Warp Scheduling & Deadlocks 📋

Key Points

  • Warp scheduler: Keeps buffer of warps, selects one every few cycles
  • NVIDIA Tesla: Max 24 warps, select 1 per cycle
  • NVIDIA Fermi: 2 warps simultaneously — each gets 16 cores + 16 LD/ST or 4 SFUs
  • NVIDIA Kepler: 4 warp schedulers per SM
  • NVIDIA Volta: 1 warp scheduler per PB (4 PBs per SM)
  • Multi-warp scheduling improves utilization: overlap ALU ops of one warp with memory ops of another → 100% utilization
  • Deadlock problem: While loop in lockstep SIMT can deadlock if thread needs another thread to set a variable
  • Volta solution: Per-thread program counter + restricted lockstep — execute code blocks concurrently
  • syncwarp() function forces reconvergence between threads
SUPER EFFECTIVE! (Exam Focus)

Deadlock scenario: Threads 0,1 wait in while(x==0) loop, threads 2,3 would set x=1 but can't reach that line due to lockstep. Volta's per-thread PC solves this.

Why schedule multiple warps simultaneously?
Click to reveal

One warp uses ALUs while another uses LD/ST units → 100% functional unit utilization instead of 50%

How did Volta solve the SIMT deadlock?
Click to reveal

Per-thread program counter + restricted lockstep: execute divergent code blocks (W, X, Y) concurrently, ensuring all threads make forward progress

#15 - GPU Pipeline & Register File 📦

Key Points

  • Reference GPU: 6 GPCs, 6MB L2, 8 memory controllers, 6 NVLink controllers
  • Each GPC: 14 SMs. Each SM: 4 PBs + 128KB L1 data cache
  • GPU pipeline: i-cache → Decode → Scoreboard → Dispatch → Register File → Execute → Writeback
  • No rename table / reservation stations — uses scoreboard for dependence tracking
  • Register file: 64KB per PB, divided into 16 banks of 4KB each
  • Block size = 1024 bits (32 threads × 32 bits) — reads all thread data at once
  • Operand Collectors: Buffer entries that collect source operands from register banks
  • Crossbar switch: N×M switch connecting register file banks to operand collectors
  • L1 Cache: Most critical — arbiter splits accesses into conflict-free subsets
  • MSHR (Miss Status Handling Register): Records cache misses, merges requests for same block
SUPER EFFECTIVE! (Exam Focus)

Register file is 64KB (huge!) with 1024-bit block size (32 threads × 32 bits). Operand collectors + crossbar handle the massive bandwidth requirement.

Why is GPU register file so large?
Click to reveal

32 threads need data simultaneously — 32×32 bits = 1024 bits per access. Need 64KB with 16 banks to sustain throughput

What are Operand Collectors?
Click to reveal

Buffers that gather source operands from register file banks via a crossbar switch before sending to execution units

#16 - Intro to Machine Learning 🧠

Key Points

  • Complex tasks (face recognition, speech synthesis) were impossible before deep learning
  • Deep learning mimics human brain processes — hierarchy of simple learners
  • Each layer computes a function (linear or nonlinear) over inputs
  • Alternating linear and nonlinear layers learns extremely complex functions
  • Computation is massively parallel and requires very high memory bandwidth
  • Very different from traditional integer/floating point programs
SUPER EFFECTIVE! (Exam Focus)

Deep learning = hierarchy of simple learners. Alternating linear + nonlinear layers. Massively parallel computation with high memory bandwidth needs.

What makes deep learning different from traditional AI?
Click to reveal

Uses hierarchy of simple learners (layers) that progressively learn complex concepts, inspired by human brain — not traditional algorithms

Why alternate linear and nonlinear layers?
Click to reveal

Linear layers alone can only learn linear functions. Nonlinear activations allow learning arbitrarily complex functions

#17 - Learning Problem Formulation 📐

Key Points

  • Training: Given inputs X and outputs Y, learn hidden function f*
  • Testing/Inferencing: Use trained model to predict output for unseen input
  • Error measurement: Absolute difference, Mean Square Error (MSE), etc.
  • Goal: Minimize error for unseen test inputs (generalization)
  • The hidden function f* is memoryless — doesn't depend on input order
  • Universal Approximator: Algorithm that can approximate ANY continuous function
  • Behavior fully controlled by parameters — just need to estimate parameters
  • Linear regression: y = w^T·x + b — fails for non-linear functions, NOT a universal approximator
SUPER EFFECTIVE! (Exam Focus)

Universal approximator: can approximate ANY continuous function in R^n by just changing parameters. Neural networks ARE universal approximators. Linear regression is NOT.

Training vs Inferencing?
Click to reveal

Training: learn weights from known input-output pairs (offline). Inferencing: predict output for unknown input using trained model (needs hardware acceleration)

What is a Universal Approximator?
Click to reveal

Algorithm that can approximate any continuous function without prior knowledge of f*, fully controlled by learnable parameters

#18 - Neural Networks & Activation 🔥
Neural Network Architecture with Activation Functions

Key Points

  • Neural networks introduce nonlinearity: output = g(w^T·x + b)
  • Activation functions: Sigmoid (0 to 1), tanh (-1 to 1), ReLU (max(0,x))
  • XOR example: Can't be solved with single linear layer (not linearly separable)
  • XOR solution: Compute a-b with weights [1,-1], then |x| = ReLU(x) + ReLU(-x)
  • Network structure: Linear → Nonlinear (ReLU) → Linear layers alternating
  • Architecture (layers, units) decided a priori — training only computes weights
  • Backpropagation algorithm used for computing weights during training
  • Deeper networks (100+ layers, millions of weights) = Deep Neural Networks (DNNs)
SUPER EFFECTIVE! (Exam Focus)

XOR requires nonlinearity! Weight [1,-1] computes a-b, then ReLU gives |a-b|. Structure: alternate Linear → Nonlinear layers. ReLU(x) = max(0, x).

Why can't a single linear layer compute XOR?
Click to reveal

XOR is not linearly separable — need nonlinear activation (ReLU) between layers to capture the function

Name 3 activation functions
Click to reveal

Sigmoid: 1/(1+e^-x) range [0,1]. Tanh: range [-1,1]. ReLU: max(0,x) — most popular, computationally simple

How is XOR computed with a neural network?
Click to reveal

Layer 1: weights [1,-1] and [-1,1] → Layer 2: ReLU on both → Layer 3: sum outputs = |a-b| = a⊕b

#19 - CNN & Convolution Operation 🔍
CNN Convolution Operation — click to enlarge

Key Points

  • Fully Connected Layer: Each input multiplied by its own weight — N inputs need N weights (expensive!)
  • Convolutional Layer: Uses small filter (R×S) instead of full weight vector — local operation
  • Convolution: Slide filter over ifmap, compute dot product at each position → ofmap pixel
  • O[h][w] = Σ_r Σ_s I[h+r][w+s] × F[r][s] (element-wise dot product)
  • NOT traditional signal processing convolution — it's cross-correlation (no sign flip)
  • CNN terminology: ifmap (input feature map), ofmap (output feature map), filter/kernel
  • Multiple channels: Each ofmap depends on ALL C input channels — unique filter per (ifmap, ofmap) pair
  • Batch processing: N images processed simultaneously for efficiency
  • 4 layer types in CNN: Convolutional, Fully Connected, ReLU, Pooling
SUPER EFFECTIVE! (Exam Focus)

Convolution = slide small filter (R×S) over large ifmap, dot product at each position. MUCH cheaper than fully connected layer. Per output pixel: C×R×S MAC operations.

Fully Connected vs Convolutional Layer?
Click to reveal

FC: N inputs × N weights (huge). Conv: small R×S filter slides over input — local operation, weight sharing, much fewer parameters

What is a MAC operation?
Click to reveal

Multiply-And-Accumulate: product I[n][c][h+r][w+s]×F[k][c][r][s] added to running sum. Per output pixel: C×R×S MACs

#20 - PE Array & Dataflow Architectures 🏛️
PE Array & Dataflow Architecture — click to enlarge

Key Points

  • Reference architecture: 2D matrix of PEs + Local Buffer (LB, like L1) + Global Buffer (GB, like L2) + Main Memory
  • PEs interconnected via Network-on-Chip (NoC)
  • Dispatcher: Complex processor that orchestrates computation, divides work among PEs
  • Loop notation: '>' means temporal (sequential), '‖' means parallel
  • Tiling: Break iteration space into sub-spaces mapped to PEs
  • 7 loop dimensions: n (batch), k (ofmap), c (channel), h, w (spatial), r, s (filter)
  • Loops can be reordered freely — no dependencies between iterators
  • Folded execution: When iterations exceed PE count, hybrid parallel+sequential
  • Barrier synchronization between loop iterations for correctness
SUPER EFFECTIVE! (Exam Focus)

Architecture: 2D PE array + LB (L1) + GB (L2) + DRAM. 7 independent loop dimensions can be reordered and parallelized freely. '>' = sequential, '‖' = parallel.

What is the reference ML architecture?
Click to reveal

2D PE array with Local Buffers (L1), Global Buffer (L2), connected via NoC, controlled by a dispatcher processor

What does '‖' mean in loop notation?
Click to reveal

The loop can be parallelized — distribute iterations across PEs. If not enough PEs, execution is 'folded' (hybrid parallel+sequential)

#21 - Stationarity: WS, IS, OS, RS ⚖️
WS / IS / OS / RS Stationarity Types — click to enlarge

Key Points

  • Stationarity: Keep certain data cached in PE's local buffer for maximum reuse
  • Weight Stationary (WS): Cache filter weights in each PE — stream inputs/outputs
  • WS: Each PE has filter for one (ifmap, ofmap) pair. Rows = channels, Columns = ofmaps
  • Input Stationary (IS): Cache ifmap tiles in PEs — stream filter weights
  • IS: Store C ifmap tiles per PE. Halo pixels at tile edges need special handling
  • Output Stationary (OS): Distribute output pixels across PEs — stream inputs and filters
  • Row Stationary (RS): Distribute rows of ifmap and filter — one PE aggregates partial sums per ofmap row
  • No Local Reuse (NLR): No stationarity — data not cached in PEs
  • Key principle: Maximize reuse of stationary data, minimize reloads
SUPER EFFECTIVE! (Exam Focus)

WS: filters stay in PE. IS: inputs stay in PE. OS: outputs stay in PE. RS: rows distributed. Goal: maximize data reuse, minimize memory traffic.

4 types of stationarity?
Click to reveal

Weight Stationary (cache filters), Input Stationary (cache ifmaps), Output Stationary (cache ofmaps), Row Stationary (cache rows)

What are Halo Pixels?
Click to reveal

Pixels at tile edges that need data from neighboring tiles for convolution — requires extra storage or inter-PE communication

What is NLR?
Click to reveal

No Local Reuse — architecture where nothing is cached in PE local buffers. Inefficient but simplest design

#22 - WS Hardware Architecture 🔧
Weight Stationary Hardware — 4 Phases — click to enlarge

Key Points

  • Spatial reuse: Read data once from memory, multicast to multiple PEs
  • Data can also flow systolically from one PE to next along row/column
  • 2D PE array for WS: Rows = channels (c), Columns = ofmaps (k)
  • Phase I: Load filter weights into PEs (each PE gets one (k,c) filter)
  • Phase II: Stream ifmap blocks along rows (one channel per row)
  • Phase III: Each PE computes convolution between input data and cached filter
  • Phase IV: Reduction — sum partial sums column-wise
  • Reduction methods: Parallel reduction (adder tree via NoC) OR Systolic transfer (pass partial sums down column)
  • Systolic transfer: Top PE sends to PE below, which adds and passes down → result exits at bottom row
SUPER EFFECTIVE! (Exam Focus)

WS Hardware: 4 phases — Load filters → Stream inputs along rows → Compute convolutions → Reduce partial sums column-wise (systolic or adder tree).

What are the 4 phases of WS execution?
Click to reveal

Phase I: Load filters. Phase II: Stream inputs. Phase III: Compute convolutions. Phase IV: Reduce (sum partial sums column-wise)

Systolic vs Parallel Reduction?
Click to reveal

Systolic: Each PE passes partial sums to next PE in column — simple, sequential. Parallel: Adder tree via NoC — faster, more complex

GPUs are crucial for modern computation because:

  • General-purpose CPUs max out at IPC of 4-6 — insufficient for heavy parallel workloads like weather simulation, image recognition, and scientific computing.
  • Programs requiring massive Instruction Level Parallelism (ILP) cannot be efficiently handled by CPUs alone.
  • GPUs solve this by having hundreds of simple ALUs for massive parallel computation.
  • GPU approach: Simple ISA + limited irregular memory accesses + hundreds of simple cores.
  • Trade-off: Dedicate chip area to ALUs instead of complex fetch/decode/schedule logic.
  • Matrix operations (core of scientific computing) have N² independent additions with no dependencies — perfect for GPU parallelism.

Key Applications:

  • Scientific simulations (weather, molecular dynamics)
  • Machine Learning / Deep Learning training and inference
  • Image and video processing
  • Cryptography and blockchain
  • Real-time 3D graphics rendering

With neat diagram, explain the rendering pipeline applicable to GPU.
▼

⚡ Answer

Graphics Rendering Pipeline — click to enlarge

The Graphics Rendering Pipeline synthesizes (renders) images through 4 main stages:

  1. Vertex Processor (Polymorph Engine in modern GPUs): Transforms object-space coordinates to world coordinates. Performs vertex shading, hull shading. In modern GPUs (Fermi+), this is a 5-stage Polymorph Engine: Vertex Fetch → Tessellation → Viewport Transform → Attribute Setup → Stream Output.
  2. Rasterizer: Converts triangles into pixel fragments by overlaying a grid. Determines which pixels each triangle covers.
  3. Fragment Processor: Computes final color of each pixel using shading models (Goraud or Phong), texture mapping, and distance fog.
  4. Pixel Engine: Populates the frame buffer (2D color matrix sent to monitor). Handles Z-depth buffering (visibility) and alpha channel (transparency 0.0–1.0).

Key concepts:

  • Triangles are the fundamental primitive — always planar, easy ray intersection.
  • PTX (Parallel Thread eXecution): NVIDIA's virtual ISA — platform independent.
  • SASS (Shader ASSembler): Device-specific native ISA, compiled from PTX via JIT.
  • Moving/rotating/scaling triangles = matrix operations → perfect for GPU parallelism.

Describe the following keywords with respect to GPU: Kernels, Threads, Blocks and Grids
▼

⚡ Answer

Kernel

A function executed on the GPU, invoked by CPU host code using the __global__ directive. When launched, it creates thousands of parallel thread instances.

Thread

The smallest execution unit on GPU. Each thread is a separate program instance that shares address space with other threads and has a unique identifier threadIdx (can be 1D, 2D, or 3D).

Block

A group of threads (1D/2D/3D arrangement). Max 768–1024 threads per block. Threads within a block can synchronize via __syncthreads() (barrier) and share data through shared memory. Identified by blockIdx.

Grid

A collection of blocks (1D/2D/3D). Blocks execute independently in any order — no inter-block synchronization. This enables scalability across different GPU sizes.

Hierarchy: Thread → Block → Grid

Index computation: globalIdx = blockIdx.x * blockDim.x + threadIdx.x

dim3 is the built-in 3-tuple type for specifying dimensions (unspecified values default to 1).

Describe the following keywords with respect to GPU: Streams, Graphs and Events
▼

⚡ Answer

Streams

A stream is a sequence of commands (memory transfers, kernel launches) that execute in order. Multiple streams execute independently with no ordering guarantee across streams.

Purpose: Overlap data transfer and computation phases. Without streams, execution is sequential: ToGPU → Compute → ToCPU. With 2 streams, one stream computes while another transfers data — reducing execution time from 3 units to 2 units (33% speedup).

Graphs

CUDA Graphs reduce the overhead of launching many short-duration kernels. A graph consists of nodes (kernels, CPU functions, memory operations, child graphs) connected by edges (dependencies).

The runtime pre-computes the execution schedule and prefetches data, eliminating per-launch overhead.

Events

Events are used for timing and synchronization between streams. They mark points in a stream's execution for measuring elapsed time or creating dependencies between streams.

GPC (Graphics Processing Cluster)

Each GPC contains:

  • Simple in-order pipeline — no rename tables or reservation stations (saves power/area)

Explain the concept of warp and its importance in GPU
▼

⚡ Answer

A warp is a group of 32 threads that are scheduled and executed together on a Processing Block (PB) using the SIMT (Single Instruction, Multiple Thread) execution model.

Key characteristics:

  • Lockstep execution: All 32 threads execute the SAME instruction simultaneously on DIFFERENT data.
  • The scheduler picks the next instruction and sends it to ALL cores in the warp.
  • If one thread's memory access is slow (cache miss), ALL threads wait.
  • This is acceptable because GPU workloads typically have regular, co-located memory access patterns.

Importance:

  • Efficiency: Single fetch/decode for 32 threads saves enormous power and area vs. 32 independent pipelines.
  • Latency hiding: When one warp stalls on memory, the scheduler switches to another ready warp — keeping ALUs busy.
  • Throughput: Multiple warps per SM enables near-100% utilization of functional units.
  • Scalability: The warp abstraction allows the GPU to scale from small to large configs transparently.

Explain how warp works in the following cases: Branch divergence and predicated execution; Varying execution times
▼

⚡ Answer

Branch Divergence & Predicated Execution
Predicated Execution with Mask — click to enlarge

When threads in a warp take different paths (if/else), it breaks lockstep — this is branch divergence.

Solution — Predicated Execution:

  • ALL threads execute ALL branch paths in lockstep.
  • Correct path: Instructions executed and committed to architectural state.
  • Wrong path: Instructions processed but results DISCARDED.
  • A 32-bit mask per warp tracks which threads should commit: bit i = 1 means thread i is on correct path.
  • Stack-based tracking for nested branches: Push 1 (correct) or 0 (wrong). Instruction committed only if ALL stack entries are 1.
  • Reconvergence point: Where all divergent threads rejoin after the branch.
Varying Execution Times

Since all threads execute in lockstep, varying execution times cause problems:

  • If one thread has a cache miss, ALL 32 threads wait for that thread's data.
  • Performance degrades when memory accesses straddle cache lines.
  • This is generally acceptable because GPU workloads have regular, co-located memory patterns — most threads access nearby data.
  • Solution: Ensure coalesced memory accesses — adjacent threads access adjacent memory locations.

Explain Warp Scheduling in GPUs
▼

⚡ Answer

The warp scheduler maintains a buffer of ready warps and selects warps for execution to maximize utilization.

Evolution across GPU generations:

  • Tesla: Max 24 warps, select 1 per cycle.
  • Fermi: 2 warps simultaneously — each gets 16 cores + 16 LD/ST or 4 SFUs.
  • Kepler: 4 warp schedulers per SM.
  • Volta: 1 warp scheduler per PB (4 PBs per SM).

Multi-warp scheduling improves utilization: overlap ALU ops of one warp with memory ops of another → 100% utilization.

Deadlock Problem (pre-Volta): While loop in lockstep SIMT can deadlock if thread A waits for thread B to set a variable, but B can't reach that code due to lockstep.

Volta's Solution:

  • Per-thread program counter + restricted lockstep.
  • Divergent code blocks execute concurrently, ensuring all threads make forward progress.
  • syncwarp() function forces reconvergence between threads.

Deep Learning is a subset of machine learning that mimics the human brain using a hierarchy of simple learners (layers).

Describe the following functions: Sigmoid, Tanh, ReLU
▼

⚡ Answer

Sigmoid Function
σ(x) = 1 / (1 + e−x)
  • Output range: (0, 1)
  • S-shaped curve, smooth gradient
  • Used for binary classification outputs
  • Drawback: Vanishing gradient problem for very large/small inputs; output not zero-centered
Tanh Function
tanh(x) = (ex − e−x) / (ex + e−x)
  • Output range: (−1, 1)
  • Zero-centered output (better than sigmoid)
  • Drawback: Still suffers from vanishing gradient for extreme values
ReLU (Rectified Linear Unit)
ReLU(x) = max(0, x)
  • Output range: [0, ∞)
  • Most popular activation function in modern deep learning
  • Computationally simple — just a threshold operation
  • No vanishing gradient for positive values
  • Drawback: "Dying ReLU" — neurons with negative input always output 0

Model the XOR function using neural networks

⚡ Answer

XOR is NOT linearly separable — a single linear layer cannot compute it. We need nonlinear activation (ReLU).

Solution Architecture:

  1. Layer 1 (Linear): Two neurons with weights:
    • Neuron 1: weights [1, −1] → computes (a − b)
    • Neuron 2: weights [−1, 1] → computes (b − a)
  2. Layer 2 (ReLU): Apply ReLU to both outputs:
    • ReLU(a − b) = max(0, a−b)
    • ReLU(b − a) = max(0, b−a)
  3. Layer 3 (Linear sum): Sum both ReLU outputs:
    • ReLU(a−b) + ReLU(b−a) = |a − b| = a ⊕ b

Describe the Weight Stationary (WS) architecture with neat diagram
▼

⚡ Answer

Weight Stationary Hardware Architecture — click to enlarge

Weight Stationary (WS) is a dataflow architecture where filter weights are cached in each PE's local buffer for maximum reuse, while inputs and outputs are streamed.

Reference Architecture: 2D PE array + Local Buffer (LB, like L1) + Global Buffer (GB, like L2) + Main Memory, connected via NoC.

2D PE Array Layout: Rows = channels (c), Columns = ofmaps (k). Each PE stores the filter for one (ifmap channel, ofmap) pair.

4 Phases of WS Execution:

  1. Phase I — Load Filters: Load filter weights into PEs. Each PE gets one (k,c) filter.
  2. Phase II — Stream Inputs: Stream ifmap blocks along rows (one channel per row). Data flows systolically from PE to PE.
  3. Phase III — Compute: Each PE computes convolution between streamed input data and its cached filter weights.
  4. Phase IV — Reduce: Sum partial sums column-wise using either:
    • Parallel reduction: Adder tree via NoC — faster, more complex.
    • Systolic transfer: Top PE sends partial sum to PE below, which adds its own and passes down — simpler, sequential.

Key Principle: Spatial reuse — read data once from memory, multicast to multiple PEs. Maximize reuse of stationary (cached) filter weights to minimize memory traffic.
